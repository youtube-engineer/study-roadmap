先に片付ける

コードとブランチの状態を揃えてから外部サービスに触る。ここを飛ばすと、設定は全部正しいのに古いコードが本番になって原因の切り分けができなくなる。

02

Supabase 本番プロジェクト

preview（vkxwdszsdrpablpotdqe）とは別のプロジェクトを立てる。無料プランはアクティブ2プロジェクトまでなので、preview と合わせてちょうど収まる。

CAPTCHA は今は入れない

CLAUDE.md 14章は「CAPTCHAも入れておく」としているが、有効にすると全ての認証呼び出しに captcha トークンが必要になる。 client.ts と copy.ts の signInAnonymously() はトークンを渡していないので、有効にした瞬間に匿名サインインが全滅する。

しかも落ちるのはサーバー側だけで、IndexedDB には書けるので画面は完全に正常に見える。「手元では動いているのにサーバーには何も入らない」という一番たちの悪い壊れ方になる。入れるなら Turnstile / hCaptcha を実装して options.captchaToken を渡す改修が先。

任意：定期クリーンアップ

0002_cleanup.sql の関数は作られるが、スケジュールはコメントアウトされたまま。走らせるなら Integrations で pg_cron を有効にしてから、同ファイル47行目以降の SQL を実行する。公開済み（is_public = true）は対象外になっている。急ぐ設定ではない。

04

Vercel

Supabase 連携（Integration）は使わないほうがいい

使うと NEXT_PUBLIC_SUPABASE_ANON_KEY / SUPABASE_SERVICE_ROLE_KEY という別名で入る。コードはどちらの名前も受けるので動く（config.ts・admin.ts の firstNonEmpty）が、同じ鍵が2つの名前で並ぶと片方の更新を忘れる事故になる。 手で入れて1本にする。

値を空にして名前だけ作らない

Vercel では名前だけ作られて値が空という状態が普通に起きる。firstNonEmpty が空を「無い」として扱うので落ち方は穏やかになるが、Supabase は丸ごとモックに落ちて保存が一切サーバーへ行かない。CLAUDE.md 14章で半日溶けたのはこれ。

NEXT_PUBLIC_SITE_URL は省略せず入れる

site-url.ts の優先順位では省略できることになっているが、フォールバック先の NEXT_PUBLIC_VERCEL_PROJECT_PRODUCTION_URL は Vercel の「Automatically expose System Environment Variables」が ON でないと存在せず、無言で localhost:3000 まで落ちる。共有URLとOGPの絶対URLが丸ごと壊れるので、明示したほうが確実。

05

ドメインが確定してから埋める

Redirect URLs を外すと必ずハマる

redirectTo が許可リストに無いと、Supabase は黙って Site URL に差し替える。しかも飛ばす先は /auth/callback ではなく Site URL の根なので、認可コードを誰も交換しないままセッションができない。「ログインしたのにログインボタンのままだ」という形で現れる。

localhost を入れ忘れると手元でログインしたのに本番のURLへ飛ばされる。オリジンが違うので IndexedDB も別物になり、手元のロードマップが持ち込まれていないようにも見える。
